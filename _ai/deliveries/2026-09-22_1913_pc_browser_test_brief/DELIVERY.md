# 任务：PC 浏览器现场测试（先不做平板）

- **Task**: 在 PC 上用桌面浏览器加载现有扩展，打开 `https://suno.com/` 做现场测试，并交付可核对的证据。
- **Result**: 本文件是测试授权和验收标准，不是测试结果。测试尚未执行。
- **允许**: Windows 上的 Chrome 或 Edge。加载已解压的扩展目录 `dist/chrome-extension/`。
- **这一轮不要做**: 平板、Kiwi、三星 S-Pen、应用商店、APK、改词库、新增 `import_review.js`。测到缺陷只记录，不在同一轮里顺手改代码。
- **现场状态**: 测完之前，suno.com 仍是 `NOT_YET_VERIFIED`。S-Pen 这一轮结束时也仍然是 `NOT_YET_VERIFIED`。

## 怎么装

1. 使用当前正式构建，不要为了测试另改注入逻辑。若 `dist/chrome-extension/` 与源码不一致，先只运行 `node scripts/build.js`，把构建日志写入交付。
2. 打开 `chrome://extensions/` 或 `edge://extensions/`，打开开发者模式，加载 `D:\Projects\Suno_Copilot\dist\chrome-extension\`。
3. 记录浏览器名称、版本，以及扩展是否启用、是否报错。

## 必须做的检查

登录墙：进不去创作页就停在能看到的页面，把登录障碍写成阻塞，不要把未看见的界面写成通过。

1. **创作区按钮**  
   列出页面上实际出现徽标的英文原文，以及旁边的中文小标题。徽标必须在控件旁边，不能出现在按钮内部。`button` 以外的普通歌词、标题、列表文字上不应有徽标。

2. **歌词编辑区**  
   在歌词框单独输入一行 `[Chorus]`，再输入一行 `Custom`。扫描后这两行文本必须保持原样，编辑区内部没有 `?` 徽标。

3. **三层卡片**  
   只点徽标，不点 Suno 自己的按钮。卡片里要同时看见人话解释、实操指引、第三层示例正文。`Custom` 这类界面项不要出现假复制条。

4. **不要触发消耗**  
   找到生成 / Create 一类会扣点数的按钮。确认它没有被徽标点击带到。测试时不要为了试功能去点真正的生成。若页面因此开始生成或出现扣点，记为失败。

5. **抽屉**  
   打开右下角速查，搜索 `Bridge`，复制应得到歌词标签而不是一句假指令。复制失败时提示必须是失败，不能显示「已复制」。

6. **滚动**  
   打开一张卡片后滚动页面，卡片仍贴在视口里的徽标附近，不能跑到滚动量之外。

## 交付

新建目录，不要覆盖本目录：

```text

```

其中至少包括：

- `DELIVERY.md`：浏览器与版本、测了哪些条、每条 PASS / FAIL / BLOCKED、未测项。
- `screenshots/`：扩展已加载、带徽标的创作区、三层卡片、歌词框内无徽标。没有截图的通过项不予接受。
- 控制台若有报错，把原文放进 `CONSOLE.txt`。

不要写「全功能已在 suno.com 验证」或「S-Pen 可用」。平板测试等这一轮 PC 证据被接受后再开。
